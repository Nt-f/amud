# Deploying the Siddur web app (PWA)

`web-dist/` is the **precompiled** app. It's fully self-contained: all
Sefaria texts, rules, fonts and the CanvasKit runtime are bundled. Nothing
is loaded from Sefaria or Google's CDN at runtime.

## Docker

`docker build` compiles the app from source (in a Flutter SDK image) and
serves it with nginx:

    docker build -t flutter-siddur .
    docker run -d -p 8088:8088 flutter-siddur    # http://localhost:8088
    # or
    docker compose up -d --build

Build options:

    docker build --build-arg SYNC_SEFARIA=1 -t flutter-siddur .      # re-download texts first
    docker build --build-arg BASE_HREF=/siddur/ -t flutter-siddur .  # serve from a sub-path

The image is built from source, but `web-dist/` on disk is not touched. To
refresh it from the same build (e.g. before using `Dockerfile.prebuilt`):

    docker build --target web-dist --output web-dist .

To deploy the precompiled `web-dist/` without building (no Flutter SDK needed):

    docker build -f Dockerfile.prebuilt -t flutter-siddur .

## Any static host

Upload the contents of `web-dist/` to any static host (nginx, Caddy,
S3/CloudFront, Netlify, GitHub Pages, …). Serve `index.html`, `sw.js` and
`manifest.json` with `Cache-Control: no-cache` so installed PWAs update.
`docker/nginx.conf` is a complete example.

For a sub-path (e.g. `https://example.com/siddur/`), rebuild with:

    BASE_HREF=/siddur/ tool/build_web.sh

HTTPS is required for installation and offline use (localhost is exempt).

## PWA / offline

- Installable: web manifest with icons and shortcuts to Siddur, Zmanim and Calendar.
- Offline-first: `sw.js` (generated by `tool/gen_service_worker.dart`)
  precaches the app shell, all 67 Sefaria text files and one CanvasKit build
  (about 17 MB) on the first visit. After that the app works with no network.
- Each deployment gets a new content-hashed cache, and old caches are removed.
- `sw.js` is the **only** service worker. `web/flutter_bootstrap.js` loads
  Flutter without `serviceWorkerSettings`, and the `flutter_service_worker.js`
  that Flutter generates just unregisters itself. Two workers fighting over
  the page caused endless reloads, so don't turn Flutter's worker back on.
- `index.html` reloads once when a new `sw.js` takes over, at most once a
  minute (a `sessionStorage` guard), so an update can't loop.

## Sefaria sources on the server

The same texts are served as a static API:

- `GET /sefaria/manifest.json`: books, versions, licenses, sources.
- `GET /sefaria/<file>.json.gz`: gzip-compressed Sefaria-format JSON for each version or index.
- `GET /sefaria/`: directory listing.

Refresh texts with `dart run tool/sefaria_sync.dart` (add `--safe-licenses`
to keep only public-domain and Creative Commons versions), then rebuild.

## Rebuilding web-dist

    tool/build_web.sh

`web-dist/` is committed, so commit it along with the source changes.

## Redeploying siddur.nt-wrks.xyz

The live site is the `flutter-siddur:latest` image running on port 8088,
behind Cloudflare. To ship the current `web-dist/`:

    tool/build_web.sh
    docker build -f Dockerfile.prebuilt -t flutter-siddur:latest .
    docker compose up -d --no-build

Installed PWAs pick up the new version the next time they're opened.
